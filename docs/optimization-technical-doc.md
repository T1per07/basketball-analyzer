# 篮球分析系统优化技术文档

> 版本: v1.0.0 | 更新: 2026-05-26

## 概述

本文档记录 2026-05-26 第六轮优化的 5 个改进点，包括根因分析、解决方案和参数选择依据。

---

## 1. R² 阈值调整: 0.10 → 0.20

### 根因分析

轨迹拟合使用 `scipy.optimize.curve_fit` 对球位置点做抛物线拟合 `y = ax² + bx + c`，拟合质量用 R² (决定系数) 衡量。

原阈值 R² = 0.10 过于宽松，导致:
- 噪声数据（球被误检测、遮挡导致的跳变点）也能通过拟合
- 这些低质量拟合产生极端角度值（出手角 > 80° 或 < 0°）
- 62/151 (41%) 的投篮出现异常角度

### 解决方案

将阈值提升至 R² = 0.20。当 R² < 0.20 时，轨迹拟合返回 `None`，进入距离回退估算流程。

### 参数选择依据

| R² 值 | 效果 |
|--------|------|
| 0.10 (原值) | 62 个坏角，噪声拟合通过 |
| 0.15 | 预计减少约 50% 坏角 |
| **0.20 (当前)** | **0 个坏角，覆盖率仍足够** |
| 0.25 | 可能拒绝过多正常轨迹 |
| 0.30 | 测试中零距离增至 37 个，过度拒绝 |

测试数据: R² = 0.20 时，3 个视频 151 投篮全部保持 100% 检测率，零距离和坏角均为 0。

### 可调参数

```
文件: backend/config/settings.py → ShotDetectionConfig
参数: trajectory_r_squared_threshold
取值范围: 0.10 ~ 0.40
建议值: 0.20 (平衡质量与覆盖率)
调优方向: 角度异常多 → 提高; 投篮漏检多 → 降低
```

## 2. 角度合理性校验: 15°-75°

### 根因分析

出手角度 `release_angle` 由抛物线起点的导数计算:
```
slope = 2a * x_start + b
release_angle = arctan(-slope) → 转为角度
```

当拟合数据质量差时:
- 点数不足（< 5 个有效点）
- 点集中在很小区域（x 变化小）
- 存在跳变异常值

这些情况导致 `arctan` 输出极端值: 接近 90°（垂直）或负值（向下出手）。

### 解决方案

在 `ShotAnalyzer.build_result()` 中增加角度范围校验:
- 出手角度: 15° ~ 75° 之外归零
- 入射角度: 10° ~ 80° 之外归零

### 参数选择依据

| 角度 | 含义 |
|------|------|
| < 15° | 几乎水平出手，现实中极罕见（除非是传球误判） |
| 15°-45° | 低弧度投篮（如快攻上篮、急停跳投） |
| 45°-60° | 标准投篮弧度（最佳命中区间） |
| 60°-75° | 高弧度投篮（如罚球、抛投） |
| > 75° | 接近垂直，不可能是投篮（可能是传球或误检） |

### 可调参数

```
文件: backend/services/shot_analyzer.py → build_result()
参数: 硬编码在条件判断中
取值范围: release_angle: [10, 80], entry_angle: [5, 85]
建议值: release_angle: [15, 75], entry_angle: [10, 80]
调优方向: 如果高弧度投篮被过滤 → 放宽上限; 如果水平误检多 → 收紧下限
```

## 3. 三级距离回退算法

### 根因分析

原代码在轨迹拟合失败时直接返回 `distance = 0.0`，导致 19 个零距离投篮。

轨迹拟合失败的场景:
1. 有效点数 < 3
2. R² 低于阈值（拟合质量差）
3. 球位置数据全是 Kalman 预测点（`ball_area = 0`）

### 解决方案

三级回退算法，确保每条轨迹都能得到合理的距离估算:

```
┌─────────────────────────────────────────────┐
│  Level 1: 球像素大小法                        │
│  公式: d = 0.241 × focal_length / ball_dia_px │
│  条件: track.points 中有 ball_area > 0 的点    │
│  精度: ★★★★★ (最可靠)                         │
└─────────────────┬───────────────────────────┘
                  │ 失败
                  ▼
┌─────────────────────────────────────────────┐
│  Level 2: 篮筐位置换算法                      │
│  公式: d = pixel_dist × (0.45 / hoop_width_px) │
│  条件: 篮筐已锁定且 hoop_pixel_width > 0       │
│  精度: ★★★☆☆ (受篮筐检测精度影响)              │
└─────────────────┬───────────────────────────┘
                  │ 失败
                  ▼
┌─────────────────────────────────────────────┐
│  Level 3: 轨迹跨度粗估法                      │
│  公式: d = horizontal_span × 0.025            │
│  条件: 轨迹有水平位移                         │
│  精度: ★★☆☆☆ (最粗略，但好过 0)               │
└─────────────────────────────────────────────┘
```

### 关键代码路径

1. `ShotAnalyzer.build_result()` — 当 `trajectory` 为 `None` 时调用 `_fallback_distance(track)`
2. `_fallback_distance()` — 按 Level 1 → 2 → 3 依次尝试
3. `_classify_by_distance()` — 根据回退估算的距离分类投篮类型

### 参数选择依据

| 参数 | 值 | 依据 |
|------|------|------|
| 篮球真实直径 | 0.241m | FIBA 标准 7 号球 |
| 篮筐真实直径 | 0.45m | FIBA 标准 |
| 摄像头 FOV | 30° | 手机主摄典型值 |
| 跨度系数 | 0.025 | 经验值: 100px 水平跨度约 2.5m |

## 4. 轨迹匹配优化: 优先选有真实检测数据的轨迹

### 根因分析

`_find_track_for_shot()` 使用三级回退匹配:
1. 精确匹配 SD 轨迹 (track_id = shot_index)
2. 时空距离匹配 (时间差 + 空间距离)
3. 最近帧匹配 (任意轨迹)

第三级回退可能选到 ByteTrack 的 Kalman 预测轨迹，这些轨迹的 `ball_area = 0`，导致距离估算失败。

### 解决方案

在第三级回退中，优先选择有 `ball_area > 0` 数据的轨迹:

```python
with_area = [t for t in candidates if any(p.ball_area > 0 for p in t.points)]
candidates = with_area if with_area else with_points
```

### 影响

- 减少选中纯 Kalman 预测轨迹的概率
- 提高距离估算的可靠性
- 不影响投篮检测数量（匹配逻辑不变）

## 5. 球大小估算: 中位数替代均值

### 根因分析

`_estimate_ball_pixel_size()` 原来用 `np.mean(areas)` 计算平均球面积。当检测框中混入异常值（如误检的大框），均值会被拉高，导致距离估算偏小。

### 解决方案

改用 `np.median(areas)` 计算中位数。中位数对异常值更鲁棒:

```
数据: [100, 120, 110, 500, 115]  (500 是异常值)
均值: 189 → 直径 13.7px → 距离偏小
中位数: 115 → 直径 10.7px → 距离更准确
```

### 同样应用于方法 2 (轨迹间距估算)

将 `np.mean(distances)` 改为 `np.median(distances)`，减少帧间跳变的影响。
